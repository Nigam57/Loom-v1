## 1. Architecture Overview

```
Loom v1
├── Frontend        Vue 3 + Pinia + vue-i18n + TailwindCSS v3
├── Build           Vite 6 + pnpm workspaces
├── Desktop Shell   Tauri v2 (Rust backend)
├── IPC             Tauri `invoke()` commands + event listeners
├── Fonts           Be Vietnam Pro (bundled) + Material Symbols (bundled)
└── Terminal        xterm.js (v6, canvas/webgl renderer)
```

**View routing** is not a router — it's a `resolvedView` query-param (`?view=terminal`, `?view=notification-preview`) combined with a sequential `v-if/v-else-if` in `App.vue`. No `vue-router` dependency exists.

## 2. Plugin System Analysis

### 2.1 What Exists

The "plugin system" consists of:

| File | Role |
|------|------|
| `src/features/PluginMarketplace.vue` | UI shell — displays a store & installed tab |
| `src/features/global/globalStore.ts` | Stores `installedPlugins: number[]` in `global-data.json` |
| `installPlugin(id)` / `removePlugin(id)` | Writes numeric IDs to the data file |

### 2.2 Why It Doesn't Work

> [!CAUTION]
> **The plugin system is entirely a UI stub. No plugin execution, loading, or runtime exists.**

Evidence from the source:

```typescript
// PluginMarketplace.vue — line 151
// [TODO/Marketplace, 2026-01-23] Connect plugin data source and replace placeholder array.
const plugins: StorePlugin[] = [];   // ← hardcoded empty array
```

- `plugins` array is **always empty**. The store tab shows nothing.
- `installPlugin(id)` only pushes a numeric ID into a JSON file. There is no loader, no sandbox, no manifest resolution, no file system copy — nothing executes.
- `removePlugin(id)` only deletes the number from the JSON file.
- There is no Rust-side plugin command. `ui_gateway/skills.rs`, `ui_gateway/project_skills.rs`, and `lib.rs` register zero plugin commands.
- The "Import Plugin" button in the Installed tab exists in template but has **no `@click` handler** attached and no backing function.

### 2.3 Skill System — Partially Implemented

The **Skill** system is a separate but similarly incomplete feature:

| Status | Capability |
|--------|------------|
| ✅ | Import a local folder via `skills_import_folder` Tauri command |
| ✅ | Remove a folder via `skills_remove_folder` |
| ✅ | Open a folder in Finder/Explorer via `skills_open_folder` |
| ✅ | List/link/unlink project skill symlinks via Rust commands |
| ❌ | No skill execution — a "skill" is just a folder path reference |
| ❌ | Skill store data is also empty: `const librarySkillSeed: SkillLibraryItem[] = []` |
| ❌ | The sync URL input field in SkillStore does nothing |

### 2.4 Summary Verdict

> [!WARNING]
> The plugin/skill system is **marketing wireframe only**. Clicking Install writes a number to a JSON file. Nothing loads, executes, or sandboxes any code. The feature is ~10% built.

## 4. UI/UX Consistency Audit

### 4.1 Design Language

The UI uses a **dark glassmorphism aesthetic** with:
- Backdrop blur (`backdrop-blur-md`) on many surfaces
- Translucent panels (`bg-white/5`, `bg-panel/60`)
- Rounded large corners (`rounded-3xl`, `rounded-2xl`)
- A single accent color (sky blue `--color-primary: 56 189 248`)

### 4.2 Gradient Usage (Flagged by User)

> Heavy gradient usage is pervasive throughout the codebase. The user explicitly wants **no gradients**. Current count of gradient instances:

| Location | Gradient Type | Impact |

| `global.css:343–344` — `--skill-modal-gradient` | `radial-gradient + linear-gradient` on skill modal | **Medium** |
| `global.css:345–350` — `--skill-card-gradient` | `linear-gradient` on skill cards | **Medium** |

> Loom v1 (Golutra) was built as a **team collaboration/chat tool with a bundled terminal**. Our goal is an **AI agent terminal IDE with multi-agent orchestration**. There is significant feature overlap but also a fundamental framing mismatch.

## 6. Recommended Next Steps (No Code Changes Yet)

> [!NOTE]
> These are observations for planning purposes — no implementation planned without explicit approval.

1. **Strip gradients** from `global.css` — replace `--app-gradient` and `--app-gradient-spot` with a flat `background-color` variable.
2. **Remove Chat/Friends** feature if Loom is not a social tool — massive reduction in dead weight (emoji-data.ts alone is 268KB).
3. **Implement plugin execution** — the stub needs a manifest format, a sandboxed loader, and Rust-side command registration.
4. **Wire search/filter UI** in SkillStore and PluginMarketplace — both have non-functional search inputs and category filters.
5. **Extract Settings sub-components** — `Settings.vue` at 96KB is a maintenance liability.
6. **Merge SkillStore and PluginMarketplace** into one parameterized component — they are near-identical.
7. **Define skill execution semantics** — what does "running a skill" mean in Loom's context? Needs a design decision before any implementation.
